1. Introduction
1.1 Purpose
This document specifies the requirements for Disha, a hackathon prototype of a proactive AI growth copilot for small Indian merchants. It is written for the three team members and for any coding agent used to build the prototype. It is the single source of truth for behaviour, numbers and scope.
1.2 Scope
Disha observes a merchant's billing, customer and inventory data, computes the three most valuable actions for the day, explains them in Telugu or English, and prepares each action for merchant approval. The prototype runs on synthetic data. In scope: reconciliation, customer re-engagement drafts, stock-out prediction with reorder drafts, an approval workflow with audit log, LLM narration with number validation, and Telugu and English voice input. Out of scope: any live Paytm API, real WhatsApp delivery, real payments, lending or insurance decisions, full accounting, multi-store support, and production security hardening.

5. Algorithms and business rules
All engines are pure functions of the data and AS_OF. They import no LLM code.
5.1 Reconciliation
1. For each bill line, expected line total = qty × price-list price on that date.
2. If recorded line total equals expected, no discrepancy.
3. If the difference equals an approved discount for that SKU and date, suppress it.
4. If the recorded digits are the expected digits with two adjacent digits swapped, classify DIGIT_SWAP. Example: 96 recorded as 69.
5. Else if qty × recorded unit price differs from the recorded line total, QTY_MISMATCH. If a stock movement has no bill line, MISSING_ITEM. If the sum of payments differs from the bill total, PAYMENT_MISMATCH.
6. Output: bill id, line, expected, recorded, difference, class, and a boolean needs_review. Never edit the ledger.
Worked example: Bill #1048, Sugar 2 kg. Expected ₹96, recorded ₹69, difference ₹96 − ₹69 = ₹27, class DIGIT_SWAP, no approved discount, so needs_review = true.
5.2 Customer segments
• Visits are distinct bill dates for a customer in the last 120 days.
• A customer with fewer than 4 visits is New.
• Median gap = median of the days between consecutive visits. Days since = AS_OF minus the last visit date.
• Severity = days since ÷ median gap.
• A customer with 4 or more visits and days since greater than 2 × median gap is At risk. Otherwise Active.
• Retention score = monthly spend × min(severity, 3).
• Wording in the UI is always "potentially at risk". Never say churned.
Worked example: Lakshmi. Median gap 14, days since 30, severity 30 ÷ 14 = 2.14, which is above 2, so At risk. Retention score = 3,200 × 2.14 ≈ 6,857, the highest of all customers.
5.3 Inventory forecast and reorder
• Velocity v = units sold in the trailing 28 days ÷ 28.
• Days left = on hand ÷ v. Shown to one decimal; "about N days" when it rounds to a whole number of days.
• Stock-out date = AS_OF + floor(days left) days.
• A SKU is flagged when days left ≤ lead time + 3 days.
• Safety buffer = ceil(2 × v). Target cover = 7 days.
• On hand at delivery = max(0, on hand − v × lead time).
• Reorder quantity = ceil(7 × v) + safety buffer − on hand at delivery.
• Festival uplift is not modelled. The UI says so.
Worked example (Ghee 500 ml): 72 ÷ 28 = 2.571 a day, which is 18 a week. Days left = 5 ÷ 2.571 = 1.94, shown as 1.9 and "about 2 days". Stock-out date = 2026-11-14 + 1 = 2026-11-15. Buffer = ceil(5.14) = 6. On hand at delivery = max(0, 5 − 5.14) = 0. Reorder = 18 + 6 − 0 = 24.
Edited example: on hand 12 gives 12 ÷ 2.571 = 4.67, shown as 4.7 days. On hand at delivery = 12 − 5.14 = 6.86. Reorder = 18 + 6 − 6.86 = 17.14, rounded up to 18.
5.4 Prioritiser
The home screen shows the top candidate from each category, in the fixed order billing, retention, inventory.
• Billing: score = absolute difference in ₹ × confidence (DIGIT_SWAP 0.9, other classes 0.7).
• Retention: score = retention score from section 5.2.
• Inventory: rank by days left ascending. An "Urgent" tag shows when days left ≤ 2.
• If a category has no candidate, it is skipped and the next best candidate from another category fills the slot.
• Ties break by candidate id so the order is reproducible.
5.5 Cash-flow projection (Phase 2)
For each of the next 30 days, forecast net cash = mean net cash of the same weekday over the trailing 8 weeks. The band is ±1.28 standard deviations of that weekday's net cash. Evaluate on a 7-day hold-out: error = absolute difference of cumulative net ÷ actual cumulative net. Target ≤ 10%. This is a proposed Phase 2 evaluation, not an MVP claim.
5.6 Number validator
1. Build the allowed set from the facts JSON: every numeric value, with variants (₹ prefix, comma grouping, one-decimal rounding, rounded whole days, percentages).
2. Normalise the narration: map Telugu digits to 0 to 9, remove commas, map English number words one to ten to digits.
3. Extract every number with a regular expression.
4. Pass only if every extracted number is in the allowed set. Dates pass if they appear in facts.
5. Reject forbidden phrases: guaranteed, approved loan, pre-approved.
6. On failure, use the template. Record fallback_used = true.

6.3 LLM contract
System prompt (fixed): "You are a narration layer for a merchant assistant. You receive a JSON object of verified facts. You must not perform arithmetic, invent numbers, infer facts that are not in the JSON, or make financial or eligibility decisions. Explain the facts in the requested language in at most 3 short sentences, at a 6th-grade reading level, and propose only the action named in the JSON. Return only JSON in the given schema."
Input: { language: "te" | "en", type: "billing" | "retention" | "inventory" | "voice_answer", facts: {...}, allowed_action: "review_discrepancy" | "approve_message" | "create_reorder_draft" | "none" }
Output schema: { headline: string (max 60 chars), explanation: string (max 3 sentences), action_label: string, message_text?: string }
Facts JSON example (inventory): { sku: "Ghee 500 ml", on_hand: 5, weekly_sales: 18, daily_velocity: 2.57, days_left: 1.9, days_left_rounded: 2, reorder_qty: 24, festival_uplift_modelled: false }
Template fallback (English, inventory): "Ghee 500 ml: 5 units on hand. You sell about 2.57 a day, so stock lasts about 2 days. Suggested reorder: 24 units." Write one Telugu template for each card type and have a Telugu speaker check them.
